E-way bill bulk JSON format explained

The files made here follow the e-way bill portal's published bulk format, "EWB JSON Attributes, Version 1.0.0621" (NIC). You never need to edit them, but this helps you read the portal's error messages.

The e-way bill file

One object with "version": "1.0.0621" and a list billLists, one entry per e-way bill:

FieldsMeaning
supplyType, subSupplyType, subSupplyDescO outward / I inward; reason code (1 Supply, 3 Export, 4 Job Work, 5 For Own Use, 8 Others, 9 SKD/CKD/Lots, 10 Line Sales, 11 Recipient Not Known, 12 Exhibition or Fairs); a description only for Others
docType, docNo, docDateINV, BIL, BOE, CHL or OTH; up to 16 characters; DD/MM/YYYY
transType1 regular, 2 bill to - ship to, 3 bill from - dispatch from, 4 both
fromGstin … fromStateCode, actualFromStateCodeSender, and the state the goods actually leave from
toGstin … toStateCode, actualToStateCodeReceiver ("URP" if unregistered), and the state the goods actually go to
totalValue, cgstValue, sgstValue, igstValue, cessValue, OthValue, totInvValueTaxable value, taxes, other charges (round off), invoice value
transMode, transDistance, vehicleNo, vehicleType, transporterId, transDocNo, transDocDatePart B and transporter
mainHsnCode, itemListMain HSN; each item with HSN, quantity, unit, taxable amount and rates

Rules the portal checks

  • Inside one state, CGST and SGST; between states, or when one party is an SEZ, IGST.
  • State codes are numbers: 3 Punjab, 7 Delhi, 27 Maharashtra… Goods to or from outside India use 99, "Other Countries" (the e-invoice uses 96 instead).
  • Bill to - ship to: GSTIN, name and state of the "bill to" party; address, place, PIN and actualToStateCode of the "ship to" place.
  • The item values plus taxes plus other charges must match the invoice value (a 2-rupee difference is allowed).
  • Distance up to 4,000 km; the transport document date not before the document date; the document date not in the future.
  • Without Part B (no mode, vehicle or transport document) the portal gives a number without validity.

The Part B (vehicle update) file

{"version": "1.0.0621", "userGstin": …, "vehicleUpdts": [ … ]}, each entry with ewbno (12 digits), transMode, vehicleNo or docNo + docDate, fromPlace, fromState and reason (1 break down, 2 transhipment, 3 others with a remark, 4 first time).
